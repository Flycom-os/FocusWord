Admin Panel Module Documentation

This document provides a detailed description of each module available in the administration panel. Each section explains the module's purpose, its main functions, and capabilities.

Analytics

URL: /admin/analytics | Resource: media-files | Min. Level: 0

The "Analytics" module is a central hub for tracking key performance indicators (KPIs) of your project. It provides administrators and managers with a comprehensive picture of user activity, content popularity, and commercial success. The main task of this section is to transform raw data into clear and understandable reports that help in making informed business decisions. The main page of the module usually features a dashboard with key metrics: number of unique visitors, total page views, traffic sources, bounce rates, and average time spent on the site. This data can be presented in the form of interactive charts and diagrams, allowing tracking of dynamics over various time periods (day, week, month, year).

In addition to general traffic data, the analytics module provides an in-depth analysis of user behavior. You can see which pages, articles, or products are most popular, how users navigate the site, and at what stages they most often leave it. For e-commerce projects, this displays sales information: number of orders, average check, conversion rate, and total revenue. Special attention is paid to sales funnels, which allows identifying bottlenecks in the checkout process. The module can also include functionality for A/B testing, allowing comparison of the effectiveness of different page versions. A flexible system for filtering and segmenting the audience (by geography, device, behavior) provides the ability to conduct detailed analysis of specific user groups. Integration with third-party services, such as Google Analytics or Yandex.Metrica, significantly expands its capabilities, combining all data in a single interface.

Products

URL: /admin/products | Resource: media-files | Min. Level: 0

The "Products" module is the core of product catalog management in any e-commerce project. It provides a full set of tools for creating, editing, organizing, and deleting product items. Through this interface, managers can easily manage all aspects of the product database. When adding a new product, a form opens with many fields: name, detailed description using a WYSIWYG editor, SKU for unique identification, price, and an optional discounted price. An important part is media content management: multiple images can be uploaded for each product, their order can be set, and a main image can be chosen.

The product management system supports complex product structures, such as variable products. For example, for clothing, variants can be created by color and size, and for each variation, a separate price, SKU, and quantity in stock can be specified. This eliminates the need to create separate cards for each variant. Products can be organized by assigning them one or more categories, which facilitates navigation for buyers. There is also functionality for inventory management: you can specify the quantity of an item in stock, enable or disable automatic deduction upon order, and configure notifications for low stock. Additional features include managing related and recommended products, setting SEO attributes (meta titles, descriptions) for each product page, and managing product status (published, draft, archived).

Product Categories

URL: /admin/product-categories | Resource: media-files | Min. Level: 0

The "Product Categories" module is designed to structure the product catalog and create a logical hierarchy that helps users easily find the products they need. Effective organization of categories directly affects site usability and, consequently, conversion. This module allows you to create, edit, and delete product categories, as well as manage their nesting. You can create parent categories (e.g., "Electronics") and nested child categories (e.g., "Smartphones", "Laptops") within them, forming a multi-level catalog tree. This approach ensures scalability and flexibility as the assortment grows.

For each category, you can specify not only the name but also a number of additional attributes. The most important of these are SEO parameters: a unique URL (slug), meta title, and meta description. Proper completion of these fields significantly improves the visibility of categories in search engines. You can also add a unique description for each category, which will be displayed on its page, and upload an image or icon for visual representation. The module interface often supports drag-and-drop for easy changing of category sorting order and hierarchy. In addition, specific filters and product characteristics can be linked to categories, allowing for faceted search (e.g., filtering laptops by screen diagonal or RAM volume).

Feedback

URL: /admin/feedback | Resource: media-files | Min. Level: 0

The "Feedback" module serves as a centralized place for collecting and processing all messages sent by users through various forms on the site, whether it's a contact form, a callback request form, or a suggestion widget. The main goal of the module is to ensure a timely response to client requests and not miss any inquiries. All incoming messages are displayed in a list that can be sorted and filtered by various criteria, such as date received, status (new, read, in progress, archived), or subject of the inquiry. For each message, basic information is displayed: sender's name, their contact details (email or phone), and the text of the message itself.

Effective handling of inquiries is ensured by a status system. A new message automatically receives a "New" status, which changes after a manager opens it. This allows easy tracking of unprocessed requests. Advanced versions of this module may include the ability to respond directly to a message from the admin panel, with correspondence with the client being saved as a single thread. Functions for assigning a responsible manager for a specific inquiry and adding internal comments visible only to employees may also be implemented. To combat spam, the module is often integrated with protection systems such as Google reCAPTCHA, and allows manually marking messages as spam.

Media Files

URL: /admin/media-files

The "Media Files" module is a file manager and central repository for all media resources used on the site. It allows managing images, videos, documents (PDF, DOCX), and other files uploaded by administrators and editors. Instead of uploading the same file multiple times for different pages or products, it can be uploaded once to the media library and then reused anywhere on the site. This not only saves disk space but also significantly simplifies file management. All uploaded files are presented in a grid or list with thumbnails for easy visual searching.

The module's functionality includes uploading files (often with drag-and-drop and multi-upload support), deleting, and renaming them. For images, basic editing tools such as cropping, rotating, and resizing may be available. An important function is the ability to set metadata for each file, in particular, `alt` (alternative text) and `title` (title) attributes for images, which is extremely important for SEO and site accessibility for people with disabilities. The module also allows organizing files into folders, creating a logical storage structure (e.g., "Products", "Blog Articles", "Banners"). Searching and filtering by name, upload date, or file type help quickly find the necessary resources.

Sliders

URL: /admin/sliders | Resource: sliders | Min. Level: 0

The "Sliders" module provides an intuitive interface for managing dynamic banners and carousels on the main and other pages of the site. Sliders are an important design element, allowing effective presentation of promotions, new products, or key messages. This module allows creating an unlimited number of sliders, each of which can be placed in a specific part of the site. For example, one slider can be created for the main page, and another for the promotions page.

For each created slider, individual slides can be added, edited, and deleted. Slide management is very flexible: for each slide, a background image can be uploaded (separately for desktop and mobile versions), text content can be added (title, subtitle), as well as a call-to-action (CTA) button leading to a specific page. The interface usually supports drag-and-drop technology, which allows easy reordering of slides. In addition, the slider settings themselves can specify parameters such as automatic scrolling speed, the presence of navigation arrows and indicator dots, and the type of animation transition between slides. This allows full customization of the appearance and behavior of the carousel without the need to intervene in the code.

Records

URL: /admin/records | Resource: records | Min. Level: 0

The "Records" module is a flexible and universal tool for creating and managing custom content types. If standard modules, such as "Articles" or "Products", are insufficient to implement specific project tasks, "Records" come to the rescue. This module can be used for anything: work portfolios, case studies, customer reviews, job listings, real estate catalogs, and much more. The main feature of this module is its abstractness and ability to be customized for specific needs. The administrator can define a set of fields that each "record" will have, which makes it an incredibly powerful tool.

Within the module, new records can be created using a predefined structure. For example, if the module is configured for a portfolio, each record can contain fields for the project name, description, completion date, a list of technologies used, and an image gallery. Records can be grouped by categories (managed in the neighboring "Record Categories" module), which provides convenient navigation and filtering. Like other content modules, "Records" support status management (draft, published), SEO parameter configuration for each individual record, and the ability to attach media files. Due to its flexibility, this module allows extending site functionality without involving developers to create new sections from scratch.

Record Categories

URL: /admin/records/categories | Resource: record-categories | Min. Level: 0

The "Record Categories" module is an addition to the "Records" module and performs the same function as categories for products or articles: it allows structuring and organizing custom content. If the "Records" module is used to create a portfolio, then categories could be, for example, "Web Design", "Mobile Applications", "Branding". If it's a recipe catalog, then categories could be "Soups", "Desserts", "Drinks". This module allows creating a hierarchical structure where each category can have a parent, which provides the ability to create complex and logical classifications.

For each category, you can specify a name, a unique URL (slug) for forming clear links, and a description. As in other categorization modules, the ability to configure SEO attributes (meta title and meta description) for category pages is extremely important here, which helps in their promotion in search engines. A simple and intuitive interface allows easy adding of new categories, editing existing ones, and managing their order and nesting, often using drag-and-drop. The presence of this module transforms an abstract set of "records" into a full-fledged, well-structured section of the site, convenient for both administrators and end-users.

Pages

URL: /admin/pages | Resource: pages | Min. Level: 0

The "Pages" module is designed for managing static website content. These are pages that are not part of a blog, product catalog, or other dynamic section. Typical examples of such pages are "About Us", "Contacts", "Terms of Use", "Privacy Policy", "Shipping and Payment". This module provides full control over the content of such pages, allowing them to be created, edited, and deleted without any programming knowledge.

The central element when editing a page is a WYSIWYG editor (What You See Is What You Get), which allows formatting text, inserting images and videos, creating tables and links, working in a visual mode similar to a regular text editor. For each page, a unique URL (slug) can be set, which is important for creating a clear site structure and for SEO. The module also includes mandatory fields for SEO optimization: meta title, meta description, and keywords. Advanced systems can support different page templates (e.g., a page with a sidebar or without it), as well as the ability to enable and disable individual blocks on the page. Managing page hierarchy (creating child pages) is also a standard function, allowing, for example, to create an "About Us" section with subsections "Our Team" and "Our History".

Articles

URL: /admin/articles | Resource: articles | Min. Level: 0

The "Articles" module is the main tool for content marketing: publishing news, blogging, creating a knowledge base, or any other section with regularly updated materials. This module provides editors and authors with a convenient environment for creating and publishing quality content. The process of creating an article is similar to working in the "Pages" module: it is based on a powerful WYSIWYG editor for formatting text, adding media files, and other content.

However, unlike static pages, the "Articles" module has a number of specific functions. Each article can be assigned to one or more categories (managed in the "Blog" module or similar), and tags can also be added to it for more precise classification. An important function is author management: you can specify the article's author from a list of registered users. There is also the ability to set a "featured image", which will be used as a thumbnail in article listings and when sharing on social networks. For each article, you can configure SEO parameters and set a custom URL. One of the key features is the ability of deferred publication: you can write an article in advance and schedule its automatic publication on a specific date and time. This allows building a content plan and maintaining publication regularity.

Blog

URL: /admin/blog | Resource: blog | Min. Level: 0

The "Blog" module often acts as a control center for everything related to article publication. If the "Articles" module is a tool for creating specific publications, then "Blog" is the place where their environment and overall structure are configured. This module typically handles the management of blog categories. For example, if a company writes about marketing, IT, and management, then these three sections will be created here. For each category, you can usually specify a name, description, and SEO attributes.

In addition to managing categories, the "Blog" module can contain global settings for all publications. For example, you can configure the URL format for articles (e.g., `site.com/blog/category/post-name`), enable or disable comments by default for new publications, and configure RSS feed parameters. In some systems, this module can also be used to manage larger structural units than just categories, for example, series of articles. This allows combining several publications on a single large topic into a sequential cycle, which is very convenient for readers. Thus, the "Blog" module performs a strategic function, determining how content will be organized, presented, and distributed, while the "Articles" module is responsible for the tactical creation of the content itself.

Users

URL: /admin/users | Resource: users | Min. Level: 0

The "Users" module is a critically important component for managing all registered accounts in the system. It provides administrators with full control over the user base. The main screen of the module is a list of all users with the ability to search, sort, and filter (e.g., by registration date, role, or status). The list usually displays basic information: username, email, role, and date of last activity.

When navigating to a specific user's profile, the administrator gains access to their detailed information and can perform various actions. Standard features include editing user's personal data (first name, last name), resetting password (sending a password reset link to email), and changing their role in the system (e.g., promoting a user to editor or demoting to a regular client). An important function is user status management: the administrator can temporarily block (deactivate) an account or completely delete it. For e-commerce projects, the user's profile may display their order history, shipping addresses, and other related information. This module is key to ensuring the security and administration of your project's community or customer base.

Roles

URL: /admin/roles | Resource: roles | Min. Level: 0

The "Roles" module implements a Role-Based Access Control (RBAC) system. It allows creating different user groups (roles) with specific sets of rights and permissions, which ensures flexibility and security in project administration. Instead of assigning rights to each user individually, you create a role (e.g., "Content Manager"), configure permissions for it (e.g., "can create and edit articles, but cannot manage products"), and then simply assign this role to the necessary users.

In this module, you can create, edit, and delete roles. When creating or editing a role, an interface opens that presents a list of all possible actions in the system (view analytics, edit products, manage users, etc.), and for each action, a permission can be set (allow/deny). For example, for the "Comment Moderator" role, you grant access only to the "Comments" module. This approach significantly simplifies permission management in large teams. If you need to change rights for an entire group of employees, you simply edit one role, and the changes are automatically applied to all users with that role. This eliminates errors and ensures strict control over who can do what in the admin panel.

Profile

URL: /admin/profile

The "Profile" module is the personal space for each administrator or editor within the admin panel. Unlike the "Users" module, which is designed to manage all accounts, this section allows the current logged-in user to manage their own data. This is an important element of personalization and security.

The primary and most important function of this module is password change. Users should be able to regularly and securely update their credentials. The process typically requires entering the old password and the new one twice for confirmation. In addition, personal information such as first name, last name, contact email (if allowed by system security policy), and avatar, which may be displayed next to the username in the admin panel, can be edited in the profile. In some systems, settings for interface personalization may also be located here, such as selecting the language of the admin panel or the color scheme (theme). This module provides users with autonomy in managing their basic settings, reducing the load on main administrators.

Settings

URL: /admin/settings

The "Settings" module is the control center for global parameters of the entire website. Changes made here affect the entire project. This section is usually accessible only to administrators with the highest level of permissions, as incorrect configuration can disrupt the site's operation. The module is typically divided into several tabs for easy navigation through numerous options.

On the "General" tab, you can specify the site's name, its brief description (slogan), upload a logo and favicon. Contact information is also entered here: address, phone, email, which can then be automatically inserted into the site's header or footer. The "Social Networks" tab allows you to specify links to the company's profiles on various social networks. In the "Mail" section, SMTP server parameters are configured for sending all system emails (registration notifications, password reset, order confirmation). This is a critically important setting for ensuring communication with users. There may also be sections for managing API keys of third-party services (e.g., Google Maps, payment gateways), enabling "Maintenance Mode", which closes the public part of the site to visitors, and configuring date and time formats.

Payments

URL: /admin/payments | Resource: media-files | Min. Level: 0

The "Payments" module is the financial hub of the project, providing detailed information about all transactions passing through the site. This section is indispensable for online stores and services that accept online payments. It allows tracking financial flows, controlling payment statuses, and promptly responding to emerging issues. The main interface of the module is a table with a list of all transactions, which can be filtered by date, status (successful, pending, error, refunded), payment method, or order ID.

For each transaction, detailed information is available: amount, currency, date and time, transaction ID in the payment system, and a link to the associated order and the user who made the payment. This allows accounting and sales managers to easily reconcile data and track payments for each order. Depending on the integration with the payment gateway, functionality for performing refunds (full or partial) may be available from this module. For example, if a client canceled an order, the manager can initiate a refund directly from the admin panel, without going to the payment system's personal account. This module is also important for analysis: it helps understand which payment methods are most popular with clients and track the number of failed transactions, which may indicate technical problems with integration.

Activity Logs

URL: /admin/activity-logs | Resource: media-files | Min. Level: 0

The "Activity Logs" module, also known as an audit log, is a system for logging all significant actions performed by users in the administrative panel. Its main task is to ensure transparency, accountability, and security. The log records "who", "what", and "when" did something. For example, if an editor changed text on the main page, the log will show an entry: "User 'editor_user' updated 'Main Page' on 01.01.2024 at 15:30".

This tool is invaluable for investigating incidents and debugging. If important content suddenly disappears from the site, the first thing to do is look at the activity log to find out who and when might have deleted it. The log allows tracking events such as users logging into and out of the system, creating, updating, and deleting any entities (products, articles, pages, users), changing settings and roles. The module interface provides powerful tools for searching and filtering records by user, event type, date, or IP address. For large teams, this is an indispensable control tool, and for administrators, a way to ensure the stability and security of the project.

Structured Data

URL: /admin/structured-data | Resource: media-files | Min. Level: 0

The "Structured Data" module is a powerful tool for SEO specialists and marketers. It allows managing microdata on the site. Microdata is a special format for providing information to search engines (Google, Yandex) about page content, using a standardized vocabulary, most often Schema.org. Properly configured structured data helps search engines better understand your site's content and can significantly improve its presentation in search results through so-called "rich snippets". For example, for a product page, its rating, price, and availability can be displayed directly in the search results.

This module automates the process of creating and implementing microdata in JSON-LD format, which is preferred by Google. Instead of manually writing markup code for each page, templates can be created. For example, a template can be set up for products that will automatically substitute the name, description, price, image, and rating from the product card fields into the corresponding Schema.org structure (`Product` type). Similarly, templates can be created for articles (`Article` type), recipes (`Recipe` type), events (`Event` type), etc. This module allows centralized management of all microdata generation rules and easy updating when standards change.

Blocks

URL: /admin/blocks | Resource: media-files | Min. Level: 0

The "Blocks" module implements the concept of reusable content. It allows creating individual pieces of information ("blocks") that can then be inserted into various parts of the site. This is an extremely convenient tool for managing content that needs to be repeated on many pages, but also needs to be updated centrally. A classic example is a block with information about a promotion, contact details, or a call-to-action. You create this block once, and then you can place it on dozens of pages. When the promotion ends, you will only need to edit one block, and the changes will automatically be reflected everywhere.

Each block, in essence, is a mini-page with its own title (for identification in the admin panel) and content, which is created using a WYSIWYG editor. This gives complete freedom in design: a block can contain text, images, videos, tables, and HTML code. Inserting a block into a page usually occurs using a shortcode (e.g., `[block id="promo-banner"]`) or through a special widget in the page builder. This approach not only saves editors' time but also ensures information consistency across the entire site. The "Blocks" module is an indispensable assistant for efficient management of repetitive content elements.

Comments

URL: /admin/comments | Resource: media-files | Min. Level: 0

The "Comments" module is designed for moderating and managing all user comments left on the site — for blog articles, products, pages, or other materials. This tool is key to interacting with the audience and building a community around your content. The module provides a centralized interface for viewing all comments in the system. They are displayed as a list indicating the author, comment text, date, and the page on which it was left.

The main function of the module is moderation. New comments can appear on the site immediately (pre-moderation disabled) or only after administrator approval (pre-moderation enabled). In the latter case, they enter a moderation queue. The moderator can approve the comment, and it will become visible to everyone, or reject/delete it. It is also possible to mark a comment as spam, which can help in training anti-spam filters. In addition, the moderator can edit the comment text (e.g., to correct typos or remove profanity) and reply to it directly from the admin panel. Effective comment management helps maintain a healthy and constructive discussion on the site.

Tags

URL: /admin/tags | Resource: media-files | Min. Level: 0

The "Tags" module (or "Labels") provides a flexible and non-hierarchical way to classify content, primarily articles and records. Unlike categories, which create a strict tree structure, tags allow describing the content of a publication using a set of keywords. A single article can have many tags, and a single tag can be assigned to many articles from different categories. This creates an additional layer of navigation and helps users find relevant content on narrow topics.

In this module, you can manage the entire list of tags used on the site. Functionality includes creating new tags, renaming existing ones, and deleting unnecessary ones. An important function is the ability to merge duplicate tags. For example, if authors used both "design" and "Design", the administrator can merge them into one to avoid confusion. For each tag, as with categories, you can set a unique URL and SEO attributes to create optimized aggregator pages that collect all materials with that tag. Often, tags are displayed on the site as a "tag cloud", where the font size depends on the frequency of tag use.

Widgets

URL: /admin/widgets | Resource: media-files | Min. Level: 0

The "Widgets" module allows managing content blocks in special, predefined areas of the site, called "sidebars" or "widget areas". Typical examples of such areas are a sidebar, a footer, or a site header. This module provides a simple and clear, often drag-and-drop, interface for adding, configuring, and arranging widgets without the need to edit template code.

The system provides a set of available widgets, which may include: "Site Search", "Tag Cloud", "Recent Posts", "Categories", "HTML Code" (for inserting arbitrary code, e.g., a banner), "Menu", and others. The administrator simply drags and drops the desired widget into one of the available areas. Each widget has its own settings: for example, for the "Recent Posts" widget, you can specify the title and the number of articles displayed. The "Widgets" module makes the site structure incredibly flexible, allowing easy changes to the content of sidebars and other areas, adapting them to current marketing tasks. This is a powerful customization tool that is in the hands of the content manager, not the developer.

SEO

URL: /admin/seo | Resource: media-files | Min. Level: 0

The "SEO" module is the control center for search engine optimization of the entire site. While SEO settings in other modules (products, articles, pages) are responsible for optimizing specific pages, this module is responsible for global, site-wide rules and tools. It is designed for SEO specialists and administrators and helps maximize site visibility in search engines.

One of the key functions is managing meta tag templates. You can set a template by which meta titles and descriptions will be generated for pages where they are not specified manually. For example, for a product card, the template might be: "Buy {product_name} for {price} at {site_name}". Another important function is the generation and management of the `sitemap.xml` file. This file informs search engines about all site pages that need to be indexed, and the module automatically updates it when new content is added. An editor for the `robots.txt` file is also often located here, which gives instructions to search engine robots on which sections of the site can be crawled and which cannot. Another useful function is the "Redirect Manager", which allows configuring redirects (e.g., 301 redirect) from old URLs to new ones, which is critically important for maintaining SEO positions when the site structure changes.
